How it works

Architecture

One SPFx package, deployed from the App Catalog. Each site collection becomes a workspace. The web part talks only to the site's own /_api, through SPFx's built-in SPHttpClient, as the signed-in user.

One list per board

Every column is a real SharePoint field. Filtering, sorting and indexes happen on the server, private boards are list permissions, and Excel and Power BI can read the data directly.

Activity log for free

List versioning records every field change with who and when. The item panel reads it to show "Status: Working on it → Done".

Private by design

Everything runs as the signed-in user. The Inbox is computed from lists they can read, so no central notification list can leak private boards.

Sets itself up

A site owner opens the page and clicks "Set up". Numbered migrations create and later upgrade every list. They are safe to re-run.

Delivery

Phases

0 · Discovery

List the organisation's boards, column types, automations and integrations in monday.com. Confirm the priorities.

1 · Core

Setup wizard, boards, groups, items, subitems, core columns, table and Kanban, item panel, My Work, templates, Excel import and export, private boards. Pilot with one or two teams.

2 · Parity

Calendar, timeline, saved views, charts, Inbox, automations, dashboards, forms, embed web parts. About 80% coverage, then a wider rollout.

3 · Extras

Date and recurring automations, formula, time tracking, connected boards, workload, Teams tab, email digests, full migration. About 90% coverage, then cancel monday.com.

  4. Migrate current items only, or updates and files as well?
  5. Do external guests use your monday.com boards?
  6. Keep the name "Work Boards", or use your own?
